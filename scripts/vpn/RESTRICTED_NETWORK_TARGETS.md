315 проверок. Основание для выбора кандидатов — сообщение клиента о доступности
Яндекса, VK, банков, Ozon и Wildberries во время ограничений.

Критерии текущего XHTTP/REALITY: DNS, TLS 1.3, ALPN `h2`, проверка сертификата
системным хранилищем. Шесть целей прошли все 21 проверку каждая.

Повторить на CRM:

```sh
python3 /opt/crm-vpn/probe_reality_targets.py --preset restricted-network --repeat 3
```

Установка выбранных целей начинается с одного узла:

```sh
python3 /opt/crm-vpn/install_operator_fallbacks.py --restricted-network --node pl
```

Установщик сохраняет приватные резервные копии, проверяет цель трижды,
сохраняет прежние входы и ключи и привязывает текущих клиентов к новым входам.
Дополнительные методы находятся внутри профилей стран и отдельного
«Автовыбор · белые списки». Обычный «Автовыбор» использует прежние методы;
Happ показывает девять пунктов, включая страны с флагами. Полный ручной список
доступен через `view=all`. Российские сайты идут напрямую через сеть клиента.

## Что это позволяет проверить

REALITY использует TLS-имя цели для маскировки. Клиент продолжает подключаться
к адресу нашего VPS; Яндекс, VK или Ozon не становятся промежуточным сервером.
Смена SNI не меняет адрес назначения и не устраняет его блокировку.
Дополнительные входы на нестандартных TCP-портах также зависят от правил оператора.

Если у оператора разрешены только определённые адреса, нужен вход, который
действительно доступен из его сети во время ограничений. Размещение в РФ само
по себе не означает включения IP в белый список. Отдельный доступный relay
может дать резервный маршрут, но его доступность и задержку нужно измерять
из проблемной сети; на текущих зарубежных VPS гарантия отсутствует.

Проверять с телефона во время ограничения: сеть и время, успешность TCP/TLS
до входа, реальную передачу через VPN и журнал Happ. Успешная серверная
проверка и работа за границей не доказывают прохождение ограничений Билайна.

Первичные документы: [белый список Билайна](https://kola.beeline.ru/whitelist-unlock/),
[Xray REALITY](https://xtls.github.io/en/config/transports/reality.html).

## Сравнение с работающей сторонней подпиской

Изучены 29 предоставленных клиентом подписок без сохранения их ссылок,
UUID, ключей или иной информации доступа в репозитории. Шесть выдавали только
профили истёкшей подписки. Среди остальных найдены 40 разных адресов входа
в сетях Selectel, CDNVIDEO и Wellserver; у всех в RIPE указана регистрация `RU`.
Регистрация сети не подтверждает физическое расположение сервера или страну выхода.
Профили названы «Нидерланды», но серверная маршрутизация из клиентского JSON не видна.

Клиент подтвердил работу одного из этих наборов на Билайне при ограничениях.
В нём пять видимых профилей используют четыре разных входа: VLESS/REALITY,
TCP без XHTTP и Vision, fingerprint `qq`, TLS-имена MAX и VK CDN.
Среди всех изученных входов семь попадают в две подсети опубликованного списка;
один из них присутствует в подтверждённом клиентом наборе.
Это усиливает гипотезу о роли адреса назначения, но не доказывает единственную
причину блокировки или доступность всей подсети для каждого абонента.

В настройках не обнаружены TLS fragment/noises; mux выключен. Есть цепочки
резервирования и прямой доступ к российским сервисам. Это клиентские настройки,
а не сведения о нагрузке, резервировании или промежуточных серверах провайдера.

Для отдельной проверки влияния транспорта добавлен установочный режим:

```sh
python3 /opt/crm-vpn/install_operator_fallbacks.py --restricted-tcp --node pl
```

Три дополнительных входа: MAX на TCP/5269, Tilda на TCP/5222,
VK CDN на TCP/6443, каждый с собственными новыми серверными ключами.
Старые входы и ключи сохраняются. Клиенты используют fingerprint `qq`;
учёт подключений проходит через тот же общий контроль лимитов.
Дополнительные методы для Happ доступны внутри «Автовыбор · белые списки» и Польши,
а также отдельными пунктами `🧪 Тест` в основной подписке.
Режим требует явного выбора одного узла для отдельной проверки.

Пилот проверяется сначала в Happ/Xray. В ранней серии серверных проверок все
21 польский метод передали HTTPS. Проверка Mihomo обнаружила ошибку REALITY
для fingerprint `qq` у всех трёх новых входов, с ML-KEM и без него; тот же вход
с fingerprint `chrome` передавал данные. По выбору клиента пилотные TCP/QQ
входы пока исключены из Clash-выдачи; существующие методы Clash сохраняются.
Это не означает проверку всех версий Happ, Koala Clash или мобильных операторов.

При последующей проверке с фактическим fingerprint `qq` все шесть пилотных
профилей (три TCP и три HTTPS/443) вернули настоящий сертификат вместо успешной
аутентификации REALITY в Xray. Поэтому раннее успешное прохождение не является
подтверждением работоспособности QQ в текущей конфигурации. Для публикуемых
пилотов выбран `chrome`; маркер `test_profile` отделён от fingerprint.
Внутренние исторические имена пилотов с суффиксом `QQ` сохранены ради совместимости
с уже установленными входами; видимые тестовые названия этот суффикс не содержат.

## Пилот на стандартном TCP/443

```sh
python3 /opt/crm-vpn/install_shared_reality_sni.py --node pl
```

На существующем польском XHTTP-входе TCP/443 добавлены три разрешённых TLS-имени
(MAX, Tilda, VK CDN). Loopback HAProxy на `127.0.0.1:14443` выбирает соответствующую
цель для рукопожатия REALITY. Публичный вход, клиентские IP, серверные ключи,
short ID и путь XHTTP сохранены. HAProxy не проксирует пользовательские VPN-данные
через CRM и не слушает публичные адреса. Приватные копии конфигурации остаются
на узле; при ошибке установки изменения откатываются.

В основной Happ-подписке каждый из шести пилотов показан отдельной строкой
`🧪 Тест`, включая три `HTTPS 443`. Это не отдельная клиентская подписка.
На сервере проверяется каждый профиль, а на ограниченном Билайне — реальное
подключение и открытие зарубежных сайтов. До исправления fingerprint клиент
сообщил, что TCP-тесты доступа не дали. Проверка исправленных профилей у оператора
ещё нужна.

После исправления все 24 польских метода передали HTTPS. Каждый из шести
публикуемых тестовых Happ-профилей отдельно прошёл валидацию и передал запрос
до проверочного сайта (HTTP 204). Оба автовыбора и сценарий отключённого UDP
также прошли. Счётчики Xray и Hysteria учитывают передачу; временная проверочная
подписка удаляется со всех узлов, включая узлы вне выбранного `--node`.

Повторные TLS-проверки этих имён по три раза со всех узлов: Tilda и VK CDN 21/21,
MAX 18/21 (Казахстан 0/3). Проверка транспорта на нашем VPS не меняет его IP
и не подтверждает обход белого списка. Результат нужно проверить с телефона
на проблемном операторе во время ограничения.

Источники регистрации: [RIPE Wellserver](https://rdap.db.ripe.net/ip/82.202.179.94),
[RIPE CDNVIDEO](https://rdap.db.ripe.net/ip/151.236.114.141),
[RIPE Selectel](https://rdap.db.ripe.net/ip/176.114.85.177).
Поддержка fingerprint `qq` описана в [Xray TLS](https://xtls.github.io/en/config/transports/tls.html).
