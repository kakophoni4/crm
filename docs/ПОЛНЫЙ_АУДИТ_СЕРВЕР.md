## 1. Архитектура на сервере (фактически)

```
Интернет
    │
    ├─ :80  nginx (хост) ──► app.crmkanasha.org  → 127.0.0.1:19090 (frontend)
    │                      api.crmkanasha.org  → 127.0.0.1:19001 (api)
    │
    ├─ :443 xray (VPN)     VLESS + xHTTP + REALITY, inbound nl2-xhttp
    │                      (после отката с 8443 — снова 443; nginx НЕ должен занимать 443)
    │
    └─ :8443 (опционально)  использовался для VPN при конфликте с certbot — не рекомендуется для REALITY

Docker (сеть crm-staging-net, только localhost наружу для app):
  crm-staging-api        → 127.0.0.1:19001:8000
  crm-staging-frontend   → 127.0.0.1:19090:80
  crm-staging-postgres   (внутренняя сеть, не публикуется)
  crm-staging-redis      (внутренняя сеть)
  crm-staging-minio      (внутренняя сеть, образ cpuv1)
  crm-staging-worker
  crm-staging-minio-init (однократно)
```

**Не используется на сервере:** Traefik, профиль `with-proxy`, `docker-compose.local.yaml` в финальном запуске.

## 5. VPN (xray) — отдельно от CRM

| Параметр | Значение |
|----------|----------|
| Сервис | `xray.service` |
| Конфиг | `/usr/local/etc/xray/config.json` |
| Inbound VPN | `nl2-xhttp`: VLESS, **xhttp**, **REALITY**, порт **443** (целевой после отката) |
| Inbound служебный | `api`: `127.0.0.1:10085`, dokodemo-door |
| Панель 3X-UI / Marzban | **Нет** |
| Подписка Happ | Старая ссылка на **:443**; порт **8443** для REALITY не подошёл |

**Конфликт, который был:** certbot/nginx заняли **443** → VPN падал с `address already in use`. Решение без Cloudflare: **VPN на 443**, CRM по **HTTP на 80**.

| Аспект | Локально (эталон) | На сервере |

| Миграции | alembic локально / testcontainers | `alembic upgrade head` в контейнере api при старте |
| Аудит релиза (код) | CONDITIONAL | Сервер ≈ **пилот prod** с ограничениями |

## 10. Что НЕ доведено до «полного prod» (из кодового аудита + деплоя)

| # | Проблема | Критичность |
|---|----------|-------------|
| 1 | **HTTP вместо HTTPS** (без Cloudflare, VPN на 443) | Высокая для публичного интернета |
| 2 | **POST /api/v1/files** — заглушка `{"id": 0}` | Высокая, если нужны вложения в чате |
| 3 | **SEED_ADMIN_*** в `.env` — убрать после смены пароля | Высокая |
| 4 | **Cron бэкапов** — `crontab` изначально не было | Средняя |
| 5 | `worker: null` в `/healthz` | Низкая (worker в отдельном контейнере) |
| 6 | Нет CI/E2E на этом сервере | Средняя |
| 7 | `docs/SECURITY_CHECKLIST.md` не пройден | Средняя |
| 8 | Дубль `psycopg[binary]` в `pyproject.toml` если `sed` дважды | Низкая (проверить) |

## 11. Рекомендуемые действия (чеклист оператора)

```bash
# 1. Статус
crm-status

# 2. VPN: только xray на 443, nginx не на 443
ss -tlnp | grep -E 'xray|:443|:80'

# 3. Убрать seed после смены пароля в UI
sed -i 's/^SEED_ADMIN_EMAIL=.*/SEED_ADMIN_EMAIL=/' /root/crm/deploy/.env.staging
sed -i 's/^SEED_ADMIN_PASSWORD=.*/SEED_ADMIN_PASSWORD=/' /root/crm/deploy/.env.staging

# 4. Cron бэкапов
apt install -y cron
(crontab -l 2>/dev/null | grep -v vps/backup || true
 echo "0 3 * * * /root/crm/scripts/deploy/vps/backup.sh >> /var/log/crm-backup.log 2>&1") | crontab -

# 5. Проверка psycopg без дубля
grep psycopg /root/crm/pyproject.toml
```

## 12. Итоговая формулировка для заказчика

**CRM на сервере в рабочем («боевом») состоянии для эксплуатации:** чаты, API, БД, worker, домен, админ — **да**.

**Полный enterprise-prod как в документации проекта:** **нет** — без HTTPS (при VPN на 443 без Cloudflare), без полноценной загрузки файлов, без формального security checklist.

**Локальный репозиторий** остаётся **эталоном кода**; **сервер** — **упрощённый production-like runtime** с VPS-оверлеями из `deploy/server/` и `scripts/deploy/vps/`.

6. Целевая схема без Cloudflare: **VPN 443**, **CRM HTTP 80**.
