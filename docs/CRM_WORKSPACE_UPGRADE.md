# Заявки, сезоны, задачи и сообщения

## Работа в CRM

- В заявках переключатель «Обычный вид / Таблица продаж» сохраняется в этом браузере. У таблицы есть виды «Продажи», «Расчёты», «Бенефициар». «Подробнее» раскрывает условия лавок, «Заявка» открывает существующую карточку.
- Рабочий сезон определяется созданием заявки в CRM, независимо от квартала в документе. Миграция относит все существующие заявки ко 2-му кварталу 2026. Администратор планирует следующий сезон с датой и временем начала; время показывается в часовом поясе браузера. Новая заявка получает сезон на сервере. Старые заявки сохраняют сезон и связи со сделками и оплатами. «Все сезоны» и «Долги всех сезонов» позволяют работать с архивом.
- Название задачи меняет постановщик или руководитель; исполнитель также может перенести срок. Изменения сохраняются в существующей истории задачи.
- Telegram получает только «Вам поставлена задача» или «У вас просрочена задача». Ни названия, ни ссылки, ни срока, ни автора в сообщении нет. Нужны настроенный бот уведомлений и привязанный Telegram сотрудника. Статус доставки виден в задаче. При смене исполнителя/срока устаревшие уведомления отменяются. Повторные попытки после ошибки — через 5 минут. После неопределённого сетевого сбоя Telegram теоретически может принять сообщение дважды: у sendMessage нет ключа идемпотентности.
- Закрытую сделку можно вернуть в рабочий статус кнопкой «Вернуть в работу», затем редактировать. Номер сделки и её история сохраняются, новая сделка не создаётся.
- В чате выбираются несколько файлов; отправка ждёт завершения загрузок. Поле ввода растёт по тексту, голосовые воспроизводятся встроенным плеером. При ошибке отправки черновик сохраняется.

## Данные и обновление

Новые миграции: 0123_sales_seasons, 0124_pricing_snapshot, 0125_task_notifications. Их необходимо применить до запуска нового API и worker. Они добавляют сезоны, сохранённые ставки новых строк и очередь уведомлений. Существующие суммы заявок миграции не пересчитывают.

Для старых заявок без сохранённых ставок неоднозначная разбивка комиссии отмечена как приблизительная; общая сумма заявки остаётся точной. Неуказанный процент бенефициара не считается нулём в интерфейсе.

Перед production: резервная копия, прогон миграций на отдельной PostgreSQL, проверка смены сезона на границе, создания/переноса задачи и привязки Telegram. Проверки на рабочей базе не запускать: тест миграций очищает public schema.

## Проверки

Изолированные регрессионные тесты: `python -m pytest tests/workspace_regression --confcutdir=tests/workspace_regression -q`.
Фронтенд: `npm run build`; тесты сообщений, оплат и темы в `frontend/tests/unit`.
Браузерная проверка с синтетическими ответами: `frontend/tests/browser/workspace-smoke.cjs` (Vite на 127.0.0.1:5177).

Полный прогон миграций и Telegram-доставка требуют отдельного тестового окружения; локальная сборка их не заменяет.

## Автосбор заявок бенефициара

Миграция 0126_benik_collection включает очередь новых входящих вложений. Worker проверяет Excel по содержимому тем же классификатором, что ручная загрузка. Импортируются только распознанные заявки бенефициара. Исходящие Excel, обычные реестры, заблокированные покупатели и неоднозначные сделки автоматически не импортируются. Закрытая сделка не открывается и её поля не меняются. В 1С и клиенту ничего не отправляется.

Результаты сохраняются в benik_collection_queue: источник, созданная заявка, причина пропуска/ошибки. created_by технически ссылается на активного администратора; признак автоматического создания и источник находятся в отчёте очереди. При ошибке чтения файла — до 12 попыток с интервалом 5 минут, затем ручная проверка. Повторный запуск исторического импорта безопасен: проверяются источник и содержимое. Ранее удалённые заявки не восстанавливаются автоматически.

Историческая граница фиксируется при установке миграции. Все импортируемые старые заявки относятся к рабочему сезону «2-й квартал 2026» независимо от периода документов. Новые заявки получают текущий сезон по моменту создания в CRM. Исходные сообщения и файлы не перемещаются.

После установки кода и миграций на сервере — сначала предварительный отчёт (без импорта):

```bash
docker exec crm-staging-worker python -m app.workers.benik_collection
```

После проверки отчёта — импорт исторических заявок:

```bash
docker exec crm-staging-worker python -m app.workers.benik_collection --apply-history
```

ready_to_import — готово; imported — создано; duplicate — уже есть; previously_deleted — ранее удалено; not_beneficiary — другой Excel; blocked — чёрный список; needs_review — требуется проверка; attachment_unavailable — файл не сохранён/недоступен; retry — временная ошибка. Итоги напечатаны последней строкой summary. Отчёт может содержать названия файлов — не добавлять его в Git.

## Высота строк выгружаемого реестра

Исправлен общий генератор Excel для заявок и бухгалтерии: перенос текста, ширина колонок и предварительно рассчитанная высота каждой строки. Длинные названия не обрезаются в обычных размерах ячеек. Значения, ИНН, даты и суммы сохранены. Нужно скачать реестр заново: ранее скачанные файлы не меняются. Предельная высота строки Excel — 409 пунктов; для текста сверх этого размера нужно вручную расширить колонку.
