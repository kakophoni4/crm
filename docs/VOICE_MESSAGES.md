# Голосовые сообщения и локальная расшифровка

Плеер поддерживает .oga/.ogg/opus/mp3/m4a/wav, перемотку и 1×/1,5×/2×.
«В текст» запускает распознавание только по запросу пользователя. Результат хранится
в metadata вложения messages.attachments.transcript; доступ совпадает с доступом к чату.
Нижний текст можно выделять и копировать. Оригинал аудио не изменяется.

## Развёртывание
Добавьте `-f docker/docker-compose.speech.yaml` к существующей команде Compose,
сохранив оба текущих env-файла и VPS override. Соберите и запустите `speech api frontend`.
Например, из /root/crm для текущей конфигурации:

```bash
docker compose --env-file deploy/.env.staging --env-file /root/crm-ai-connection.env \
  -f docker/docker-compose.staging.yaml -f deploy/server/docker-compose.vps.yaml \
  -f docker/docker-compose.speech.yaml up -d --build speech api frontend
```

Первичная сборка скачает модель small. Во время распознавания сеть speech изолирована:
аудио остаётся на сервере, внешних API нет. Порт на хост не опубликован.
CPU: 2 потока, лимит RAM 2 ГБ, 1 активное распознавание, до 4 задач вместе с очередью.
Ограничения: 20 МБ, 10 минут. Длинные файлы и ошибки отображаются с возможностью повторить.
Распознавание может ошибаться, особенно в именах и суммах.

API отвечает сразу состоянием задачи, браузер проверяет результат каждые 3 секунды.
При перезапуске speech незавершённые задачи нужно повторить кнопкой. Полученные
результаты сохраняются в БД, завершённые результаты без открытого чата доступны
в памяти speech в течение часа. Кнопка повторно использует существующую задачу.

Проверка: `docker compose` с теми же аргументами `ps speech`; затем голосовое → «В текст».
Проверка настоящей модели и сборки образа требует сервера/Docker и загрузки весов;
локальные тесты API используют подмену HTTP-сервиса.

Основа распознавания: https://github.com/SYSTRAN/faster-whisper
